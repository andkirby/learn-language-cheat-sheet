# Deutsch Cheat Sheet — Site Plan / SoT

> This file is the source-of-truth plan for the **German** page
> (`deutsch/index.html`). Keep it short, explicit, and implementation-oriented.
> When agents change this page, update this file first, then the UI.

## 1. Product goal
Create a single-page, mobile-first German grammar cheatsheet for a Russian-speaking learner. It should be installable to a phone home screen as a PWA, work offline after the first load, and make the most common grammar patterns retrievable in 1–3 taps.

## 2. Primary use cases
1. “Which case is this and what question does it answer?”
2. “Which article/pronoun ending do I need?”
3. “Where does the verb go in this sentence?”
4. “What happens with modal/separable/perfect constructions?”
5. “What changes in subordinate clauses?”
6. “Which prepositions force Akkusativ/Dativ/Genitiv?”
7. “Show one short example, then a deeper explanation if I tap.”

## 3. Information architecture
The UI is one page with these blocks:
- Start / Quick rules
- Cases
- Articles & possessives
- Personal pronouns
- Prepositions
- Sentence order
- Verb bracket & verb constructions
- Subordinate clauses
- Relative clauses / um…zu / damit
- Adjective endings & noun changes
- Quick practice

## 4. Navigation
- Mobile: sticky bottom navigation with 5 high-frequency destinations: Cases, Forms, Order, Clauses, Verbs.
- Desktop/tablet: same navigation remains usable; content width is capped.
- Top search filters visible cheat cards by keywords such as “wem”, “modal”, “weil”, “Dativ”.
- Every section has an anchor id and is reachable from the bottom nav / quick jump chips.
- Scroll position updates active nav state (`NAV_MAP` in `index.html` maps
  non-nav sections: preps→Cases, extras→Forms; practice/install-help clear the
  highlight). Active item carries `aria-current="true"`.
- While a search query is active (`body.searching`), the hero and jump chips
  are hidden so results come first.

## 5. Interaction model
- Key grammar tokens are tappable chips/buttons.
- Tap opens a bottom-sheet dialog with: meaning, rule, one positive example, one contrast/example when useful.
- Tables are horizontally scrollable only when unavoidable; prefer compact responsive grids.
- “Show answer” interactions are used in Quick practice, never hidden behind hover-only UI.
- Search should not destroy page state; clearing search restores all cards.

## 6. Content principles
- Russian explanation first; German terminology retained.
- Examples stay short and natural.
- Prefer rules that explain form + position + trigger.
- Mark exceptions only when they are high-value for A1–B1.
- Avoid overloading the first layer; detailed notes live in tap-to-open explanations.

## 7. Grammar coverage (current baseline)
### Cases
- Nominativ: Wer? Was?
- Akkusativ: Wen? Was?
- Dativ: Wem?
- Genitiv: Wessen?
- Wechselpräpositionen: Wo? → Dativ, Wohin? → Akkusativ (with the movement/location caveat stated clearly).

### Articles
- definite: der/das/die/die → den/das/die/die → dem/dem/der/den → des/des/der/der
- indefinite: ein/ein/eine → einen/ein/eine → einem/einem/einer → eines/eines/einer
- kein / possessives follow the ein-word pattern.

### Personal pronouns
- ich/mich/mir; du/dich/dir; er/ihn/ihm; sie/sie/ihr; es/es/ihm; wir/uns/uns; ihr/euch/euch; sie/sie/ihnen; Sie/Sie/Ihnen.

### Possessives
- mein, dein, sein, ihr, unser, euer, ihr, Ihr.
- Endings by case/gender/plural.

### Sentence structure
- Main clause: finite verb in position 2.
- Question: finite verb first (yes/no), W-word first + finite verb second.
- Modal: finite modal in V2, lexical infinitive at the end.
- Perfect: haben/sein in V2, Partizip II at the end.
- Separable verbs: prefix at the end in main clauses.
- Subordinate clause: finite verb at the end after weil/dass/wenn/obwohl/ob/etc.
- Coordinators und/aber/denn/oder/sondern do not force verb-final.
- Inversion after a leading adverb/phrase: Heute muss ich …
- TeKaMoLo as a helpful default, not an absolute law.

### Advanced high-value constructions
- um … zu vs damit
- relative clauses
- Konjunktiv II: würde + Infinitiv; wäre/hätte/könnte/müsste/sollte
- passive: werden + Partizip II
- double infinitive note for modal-perfect constructions (advanced note only)

### Nouns/adjectives
- Dativ plural usually +n on noun where possible.
- Genitiv masculine/neuter often -s/-es.
- N-declension: den/dem/des Studenten etc.
- adjective ending overview after der-words and ein-words.

## 8. PWA requirements (implemented)
- This page is one language of the hub (`../index.html`); see `../README.md`
  for site structure and `../docs/ADD_LANGUAGE.md` for the per-language model.
- `./manifest.webmanifest` (in this folder): standalone display, RU locale,
  theme `#172033`, background `#f6f7fb`, icons 192/512 + 512 maskable.
- Icons generated by `tools/make_icons.py` (repo root, stdlib only) with mark
  `DE` into `./icons/`. `icon-180.png` is the apple-touch-icon.
- Shared `../sw.js` (repo root) caches all language shells; this page
  registers it as `../sw.js`. **Bump `CACHE_VERSION` there after any asset
  change on any page.**
- Install button uses `beforeinstallprompt` when supported and hides on
  `appinstalled`; iOS gets manual “Share → Add to Home Screen” instructions.
- Must be served from HTTPS (or localhost) for full PWA install/service-worker
  behavior — GitHub Pages satisfies this.

## 9. Accessibility / ergonomics
- Minimum 44px effective touch targets for primary controls (chips may render
  smaller visually with expanded hit areas — see `.design/DESIGN_SYSTEM.md`).
- Visible focus states (`--accent` outline, both themes).
- High contrast in light and dark themes; no information encoded by color alone.
- Reduced-motion preference respected.
- Dialog closes with Escape and backdrop tap.
- Font stack uses system fonts; no external font dependency.
- Works without JavaScript (noscript: answers visible, dead controls hidden).

## 10. Update protocol for future agents
When updating:
1. Update this `SITE_PLAN.md` first if scope/coverage/interaction changes.
2. Keep all existing anchors stable unless a migration is documented.
3. Add new tappable explanations to the `DETAILS` object in `index.html`.
4. Keep first-layer cards concise; put depth in dialogs.
5. Increment `CACHE_VERSION` in the shared root `sw.js` after asset changes.
6. Test at ~390px mobile width and desktop width.
7. Verify installability, offline reload, keyboard navigation and no horizontal page overflow.
8. UI/design changes follow `.design/DESIGN_SYSTEM.md` (tokens, components,
   a11y) and are logged in `.design/decisions.md`. `AGENTS.md` is the entry
   point for agents; `UI_AUDIT.md` tracks verified issues.
